## Section: Good Fits

### Eyebrow

// Good fits

### Heading

If your team does the same admin task every week, it is probably worth looking at.

### Intro copy

The first step is not a big software project. It is finding one annoying process where automation can save time quickly.

### Example bullets/cards

A staff member copies the same job details from one system into another

Someone rebuilds the same weekly report from spreadsheets and exports

Work orders, quotes or attachments arrive by email and need to be checked

Managers only find data problems after the report is already wrong

Different systems have different names, job numbers or customer details

Important admin tasks rely on one person remembering the exact steps

## Section: What I Can Build

### Eyebrow

// What I can build

### Heading

Automation that gives your team time back.

### Intro copy

I build practical tools that sit around your existing software, documents and spreadsheets. The outcome should be simple: less busywork, faster processes and fewer avoidable mistakes.

### Service cards

#### Automate repetitive admin

Remove the boring handoffs: copying, checking, renaming, matching, filing, chasing and updating records.

#### Turn messy files into usable information

Pull useful details out of emails, PDFs, spreadsheets, forms and exports so your team can review them faster.

#### Find data problems before they become reporting problems

Flag missing fields, duplicates, inconsistent job details and other issues while they can still be fixed.

#### Use AI where it actually helps

Use AI for classification, summaries, first-pass checks and review queues — with humans approving important work.

#### Build safe internal tools

Create practical tools around your current workflow, with clear review steps instead of fragile spreadsheet workarounds.

## Section: First Step

### Eyebrow

// First step

### Heading

Start with one workflow, not a huge transformation project.

### Steps

1. You show me the admin task or process that wastes the most time.

2. I map where the information starts, where it needs to go, and where mistakes happen.

3. I tell you what can be automated, what should stay human-reviewed, and what is not worth building.

4. If there is a clear win, I build the smallest useful version first so you can see whether it actually helps.
